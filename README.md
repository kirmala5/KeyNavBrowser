# KeyNav Browser

Настольный браузер на **WPF + WebView2** с полноценной клавиатурной навигацией:
перемещение по странице и по ссылкам **без мыши**.

Реализовано по техническому заданию «Разработка настольного веб-браузера с управлением с клавиатуры».

---

## Быстрый старт

### Готовая сборка

```
publish\KeyNavBrowser\KeyNavBrowser.exe
```

Самодостаточная сборка (self-contained, win-x64) — .NET устанавливать не нужно.
Требуется только **Microsoft Edge WebView2 Runtime** (на Windows 11 присутствует по умолчанию).

> Папка `publish/` исключена из Git — 133 МБ бинарников в репозитории быть
> не должно. Собранный `KeyNavBrowser.exe` выкладывайте в раздел
> **Releases** на GitHub: `Release → Draft a new release → Attach files`.

### Сборка из исходников

```powershell
cd src
dotnet build KeyNavBrowser.slnx -c Release
```

Запуск в режиме разработки:

```powershell
cd src\KeyNavBrowser
dotnet run
```

Опубликованный исполняемый файл (portable, без установленного .NET):

```powershell
dotnet publish src\KeyNavBrowser\KeyNavBrowser.csproj -c Release -r win-x64 --self-contained true -o publish\KeyNavBrowser
```

> **Отклонение от ТЗ:** в ТЗ указан .NET 8, в системе установлен только .NET 10 SDK
> (нет ни .NET 8 SDK, ни Desktop Runtime 8). Проект собран под `net10.0-windows`.
> Код не использует API, появившихся после .NET 8, и переносится на .NET 8
> сменой строки `TargetFramework` в `KeyNavBrowser.csproj`.

## Управление с клавиатуры (раздел 4 ТЗ)

Клавиши работают, когда фокус находится **на веб-странице**.

| Клавиша | Действие |
|---------|----------|
| `W` | прокрутка вверх (шаг 80 px по умолчанию, настраивается 50–100) |
| `S` | прокрутка вниз |
| `A` | прокрутка влево |
| `D` | прокрутка вправо |
| `ПРОБЕЛ` | прокрутка на один экран вниз (90 % высоты окна) |
| `Q` | предыдущая ссылка |
| `E` | следующая ссылка |
| `1` … `9` | переход по ссылке с соответствующим номером |
| `ENTER` | открыть выделенную ссылку в текущей вкладке |
| `ESC` | снять выделение ссылки |

Обход ссылок идёт **в порядке DOM** (сверху вниз, слева направо); с последней ссылки
`Q` переходит на первую, с первой `E` — на последнюю.

**Пока фокус в поле ввода** (адресная строка, `input`, `textarea`, `select`,
`contenteditable`) клавиши `W/A/S/D/Q/E` и цифры вводятся как обычный текст —
навигация приостранивается. Клавиши распознаются по `event.code`,
поэтому работают и при русской раскладке.

### Нумерация ссылок

Каждой видимой ссылке присваивается порядковый номер, который рисуется **поверх неё**
оранжевой плашкой. Номера **1–9** выделены цветом — по ним работает быстрый переход;
номера от 10 и выше серые, потому что клавиш для них нет.

Номера обновляются при прокрутке, изменении размеров окна и любых изменениях DOM
(SPA, бесконечная лента). Ссылки, скрытые через `display:none`, `visibility:hidden`
или помеченные `aria-hidden`, в нумерацию не попадают.

Отключается в настройках («Показывать номер поверх каждой видимой ссылки»).

### Режимы отображения контента

Переключаются прямо на панели навигации (список справа от адресной строки) либо
в настройках. Режим применяется сразу, без перезагрузки страницы.

| Режим | Что скрыто |
|-------|-----------|
| **Только текст** | изображения, видео, `iframe`, `canvas`, `svg` |
| **Текст + изображения** | только видео и `iframe` |
| **Текст + видео** | изображения и `svg` (видео остаётся) |

Скрытие выполняется через `display: none`. Фоновые изображения (`background-image`)
не затрагиваются: в ТЗ перечислены только конкретные элементы, а вмешательство
в фон ломает тёмные темы и вёрстку сайтов.

### Открытие ссылок в текущем окне

Все переходы — и ссылки с `target="_blank"`, и вызовы `window.open()` — открываются
**в текущей вкладке**: отдельные окна Chromium не создаются. Механизм двухуровневый:

1. скрипт в странице заранее переписывает `target="_blank"` на `_self`
   (исходное значение сохраняется в `data-keynav-target`), у форм — то же самое;
2. `CoreWebView2.NewWindowRequested` перехватывает всё, что всё же попыталось
   открыть новое окно, и переносит переход в текущую вкладку.

Поведение можно изменить в настройках («Открывать … в новой вкладке»), но по умолчанию
действует режим из ТЗ — текущее окно.

## Горячие клавиши

| Сочетание | Действие |
|-----------|----------|

| `Ctrl+W` | закрыть вкладку |

## Где хранятся данные

```
%APPDATA%\KeyNavBrowser\
├── settings.json      настройки
├── history.json       история посещений
├── bookmarks.json     закладки
└── WebView2Profile\   профиль Chromium (cookies, кэш)
```

Файлы можно удалить для полного сброса.

Если `%APPDATA%` недоступен для записи (сетевой профиль, ограничения политик),
браузер не падает: профиль и кэш переносятся во временную папку, а при запуске
показывается предупреждение — иначе «забытый» вход на сайты был бы незаметен.

## Тестовая страница

Скопируйте `tests\keynav-test.html` и `tests\keynav-target.html` в одну папку и откройте
`keynav-test.html` в браузере (или введите путь в адресную строку KeyNav Browser).

Страница содержит 19 ссылок в известном порядке, поля ввода (`input`, `textarea`,
`select`, `contenteditable`), блок шириной 3000 пикселей и длинную прокрутку —
всё это нужно для проверки клавиатурной навигации вручную.

Дополнительно на ней есть:

- **медиа-блок** (`img`, `svg`, `canvas`, `video`, `iframe`) — для проверки трёх
  режимов отображения контента;
- **ссылки с `target="_blank"`, форма с `target="_blank"` и вызов `window.open()`** —
  для проверки открытия в текущем окне;
- **скрытая ссылка** (`display:none`) и **ссылка с `aria-hidden`** — они не должны
  получать номера.
